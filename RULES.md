# RULES — How We Share This Repo

Two Muse instances work here. These rules keep us from stepping on each other.

---

## 1. The Golden Rule: Log Every Change

**After EVERY push, leave a note in `.muse/log/`.**

Filename: `YYYY-MM-DD-HHMM-<your-name>.md`
Example: `2026-10-11-1830-muse1.md`

Format:
```markdown
# 2026-10-11 18:30 — Muse #1

## What I changed
- Fixed product photos for ashwagandha, collagen, probiotic

## Why
- Pages were showing wrong products' images

## Files touched
- images/products/ashwagandha-ksm66.jpg (new)
- build.py (updated image refs)

## For Muse #2
- No action needed / Please review X / Heads up Y
```

**Read the other Muse's logs before you start work.** If they just changed something you're about to touch, coordinate.

---

## 2. Never Hand-Edit Generated Files

- `index.html` → generated by `build.py`
- `products/*.html` → generated by `build.py`

Edit `build.py` (the product data), then run `python3 build.py`.

---

## 3. Pull Before You Push

```bash
git pull origin main
# ... make your changes ...
git add .
git commit -m "Clear description of what changed"
git push origin main
```

If there's a merge conflict, **do not force-push**. Read the other Muse's log, figure out what they changed, resolve manually.

---

## 4. Product Data Rules

Every product in `build.py` MUST have:
- Correct ASIN (verify on Amazon.ca)
- Correct product name (match the Amazon listing)
- Price (approximate is fine, update quarterly)
- Correct product image (the ACTUAL product, not a similar one)
- Affiliate link with `?tag=zeroregretb04-20`

**Photo rule (learned 2026-10-11):** Wrong-product photos make the site look like a scam. Every product page must show THAT product. When in doubt, use the official Amazon product image.

## 6. Communication (updated 2026-10-11 21:08 PDT — per Kirpal's directive)

- **Muse-to-Muse:** Coordinate directly. Telegram group "Muse bros" for fast visible pings; `.muse/log/` for the durable record. Kirpal can see everything but is NOT the relay — he stays out of the loop.
- **Token burn:** Keep group messages short and batched. No chatter, no FYI pings — one message per update or decision.
- **Kirpal:** Tag him only when a real decision is genuinely his. Everything else, resolve between the two Muses.
- **Decisions:** If you change something the other Muse might disagree with, say WHY in your log

---

## 7. Never Do This

- ❌ Force-push to `main`
- ❌ Delete the other Muse's log entries
- ❌ Change the affiliate tag (`zeroregretb04-20`)
- ❌ Remove the Amazon Associate disclosure
- ❌ Add fake prices, ratings, or reviews
- ❌ Deploy without running `build.py` first
